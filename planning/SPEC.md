**状态：** 已确认

## 一、产品概述

### 1.1 产品定位

一款帮助用户规划旅游行程的工具类产品，核心价值是**减少用户做攻略的时间成本**，提供「真实、可执行」的行程推荐。

### 1.2 产品模式

分两个独立入口，逻辑完全分开：

| 入口 | 触发条件 | 用户状态 | 核心价值 |
|---|---|---|---|
| 行程规划 | 用户已确定目的地 | 有明确目的地 | 帮用户把「去某地玩N天」落地成每日具体安排 |
| 随机玩 | 用户无明确目的地 | 无方向 | 根据当前位置/预算/天数，给用户一个目的地灵感 |

### 1.3 核心用户故事

- **用户A（行程规划）：** 我想去成都玩3天，不想自己做攻略，希望有个现成的行程告诉我每天去哪、吃什么、住哪。
- **用户B（随机玩）：** 我这周末不知道去哪，但不想在家闲着，给我推荐个适合的地方和玩法。
- **用户C（编辑行程）：** 系统给的行程里有个景点我不想去，我想换成一个附近的替代。

## 二、功能规格

### 2.1 行程规划入口

#### 2.1.1 目的地选择

**交互方式：** 三级联动 Picker（省 → 市 → 区/县）

**规则：**
- 选择省后，展示该省所有地级市
- 选择市后，展示该市所有区县/县级市（直辖市直接展示区县）
- 用户可同时选择多个目的地（多选模式）：多个市、多个县、或市+县混合
- 已选目的地以 Tag 形式展示，点击 × 可删除
- 支持搜索框输入市/县名进行模糊匹配并快速添加

**数据结构：**
```
已选目的地列表：[城市A, 城市B, 县C, 县D]  ← 最多支持5个
```

#### 2.1.2 行程参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 出发日期 | Date | 必填 | 最早为今天，最远为1年后 |
| 游玩天数 | Integer | 必填 | 范围 1-14 天 |
| 游玩方式 | Multi-select | 必填 | 至少选一项 |
| 补充说明 | Text | 选填 | 最多 200 字 |

**游玩方式选项（7选N）：**
1. 轻松度假（ Scenic 慢节奏，不赶景点）
2. 网红打卡（追求出片率高的景点）
3. 寻找美食（以吃为核心，景点为辅）
4. 亲子友好（适合带小孩，无危险项目）
5. 文化探索（博物馆、历史古迹为主）
6. 户外徒步（亲近自然，有体力消耗）
7. 购物休闲（商圈、免税店、特产采购）

**补充说明示例：** "想看日出"、"不吃辣"、"带老人"、"想泡温泉"

#### 2.1.3 行程生成

**输入 → 输出：**
- 输入：目的地列表 + 日期 + 天数 + 游玩方式 + 补充说明
- 输出：按天编排的行程计划

**行程内容结构（每项）：**

| 类型 | 字段 | 说明 |
|---|---|---|
| 景点 | 名称、地址、游览时长、简短描述、交通提示 | 每天 2-4 个景点 |
| 美食 | 餐厅名、地址、推荐菜、人均消费 | 每天 1-2 家 |
| 住宿 | 酒店名、地址、价格区间、推荐理由 | 每天 1 家 |

**交通衔接：** 每两个景点之间给出交通提示（步行/打车/公交，说明时长）

**行程编辑：**
- 支持删除某项（滑出或点击删除图标）
- 支持调换顺序（拖拽）
- 支持添加备注（点击编辑）

#### 2.1.4 行程导出

- **文字复制：** 一键复制为格式化文本（方便微信粘贴发送）
- **小程序分享：** 生成分享卡片发到微信对话

### 2.2 随机玩入口

#### 2.2.1 用户输入

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 当前位置 | GPS 或手动输入城市 | 必填 | GPS 需要用户授权 |
| 游玩天数 | Integer | 必填 | 范围 1-7 天 |
| 人均预算 | Range-select | 必填 | 5档 |
| 偏好方式 | Multi-select | 选填 | 同行程规划入口 |

**预算选项：**
1. 500元以下（周边穷游）
2. 500-1000元（周末轻度假）
3. 1000-2000元（标准旅游）
4. 2000-5000元（品质游）
5. 5000元以上（高端/出境）

#### 2.2.2 推荐逻辑

**目的地发现算法：**

```
Step 1: 根据天数判断出行半径
  - 1天：≤ 100km（周边）
  - 2天：≤ 300km（邻城）
  - 3-4天：≤ 800km（高铁可达）
  - 5-7天：≤ 2000km（飞机可达）

Step 2: 根据预算筛选目的地
  - 匹配该预算范围内典型消费水平的目的地

Step 3: 偏好方式匹配
  - 目的地标签 vs 用户选择的偏好方式

Step 4: 综合排序输出 Top 3
  - 综合分数 = 距离分(30%) + 预算匹配(30%) + 偏好匹配(40%)
```

#### 2.2.3 推荐结果展示

- 展示 Top 3 推荐目的地
- 每个目的地显示：
  - 目的地名称 + 距离
  - 推荐理由（一句话）
  - 预览行程概况（X天X夜 / 主要景点数 / 预算区间）
  - 「查看详情」按钮 → 展开完整行程

---

### 2.3 个性化系统（后续版本）

#### 2.3.1 冷启动方案（v2.0）

用户每次成功生成行程后：
- 记录：目的地列表、游玩方式、补充说明关键字
- 生成用户标签向量：[海滨偏好:0, 美食:1, 古镇:0, ...]
- 后续推荐时优先命中标签

#### 2.3.2 协同过滤方案（v3.0）

用户量 ≥ 1000 后：
- 构建「用户-目的地」评分矩阵
- 计算用户相似度（余弦相似度）
- 对未访问目的地做评分预测
- 按预测分排序推荐

## 四、数据来源

| 数据类型 | 来源 | 优先级 | 更新频率 |
|---|---|---|---|
| 景点/餐厅/酒店 POI | 高德地图 API | P0 | 实时 |
| 行政区划 | 民政部公开数据 | P0 | 年度 |
| 行程内容描述 | AI 生成（基于 POI） | P0 | 即时 |
| 小红书精选内容 | 爬虫（非登录态） | P2 | 定期 |

---

## 五、异常处理

| 场景 | 处理方式 |
|---|---|
| 高德 API 超限/失败 | 展示缓存 POI 或友好提示「服务繁忙」 |
| AI 生成失败 | 回退到预设模板行程（每个热门城市一套） |
| 无 POI 结果 | 提示「该地区暂无数据，试试附近目的地」 |
| 用户未授权 GPS | 展示手动输入城市的入口 |
| 网络请求失败 | 断路器保护 + 重试机制（最多3次） |
