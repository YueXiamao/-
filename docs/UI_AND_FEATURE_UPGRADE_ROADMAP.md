# 小程序 UI 与整体功能升级落实方案

更新时间：2026-04-30
适用项目：旅行计划吧微信小程序
执行对象：Codex

## 1. 升级目标

当前项目已经具备“目的地选择、参数填写、行程生成、随机玩推荐、我的行程、登录授权、后端请求兜底”等主能力。下一阶段不再以堆功能为主，而是把产品升级到更完整、更可信、更像旅行应用的状态。

本次升级目标：

- 让首页、规划、随机玩、结果、我的五个核心模块形成统一的旅行产品气质。
- 减少解释性长文案，改为更直观的选择、卡片、路线、状态反馈。
- 强化行程结果的可用性，让用户能继续编辑、保存、查看和复用。
- 增强错误、加载、空态、网络异常、后端慢响应等真实使用场景。
- 优化性能，减少重复请求、大对象存储、无意义 setData 和资源浪费。
- 为上线和后续持续迭代建立稳定的设计与工程基线。

## 2. 设计系统方向

### 2.1 视觉定位

产品气质：轻快、有出发感、可信、简洁。

它不应该像传统后台工具，也不应该像营销落地页。更适合的方向是“旅行口袋助手”：首屏有旅行氛围，核心操作清楚，行程内容可扫描，结果页可信且能继续修改。

### 2.2 色彩策略

继续沿用当前绿色主色与暖橙辅助色：

- 绿色：用于规划、确认、保存、成功、主要按钮。
- 暖橙：用于随机玩、灵感、预算、推荐亮点。
- 背景：浅米白、浅绿色灰、白色内容面。
- 禁止方向：大面积紫蓝渐变、过度霓虹、高饱和装饰色、纯黑背景。

### 2.3 图片与背景策略

保留并扩展 `frontend/assets/backgrounds/` 的城市背景体系，但使用方式要克制：

- 首页可以使用更有旅行感的场景图组合。
- 目的地、参数、结果页使用低对比度背景图加遮罩。
- 背景不承载关键信息，不干扰按钮、表单和行程文本阅读。
- 随机玩推荐卡可按推荐目的地类型匹配山水、海岸、都市、江南、雪山等背景。

### 2.4 组件策略

统一沉淀以下组件语言：

- 页面骨架：`page`、`page-bg`、`page-hero`、`page-content`、`bottom-bar`
- 内容面板：`surface-card`、`glass-card`、`section-panel`
- 元信息：`meta-chip`、`status-pill`、`route-tag`
- 状态：`state-block`、`state-title`、`state-text`、`state-action`
- 操作：`btn-primary`、`btn-secondary`、`btn-ghost`、`icon-button`

减少“卡片套卡片”。行程结果这种信息密集页，应更多使用时间线、分割线、折叠区和操作栏，而不是一层层大卡片。

## 3. P0 必须优先执行

### P0-01 修复中文编码与文案可读性检查

目标文件：

- `frontend/app.json`
- `frontend/pages/index/index.wxml`
- `frontend/pages/plan/destination/destination.wxml`
- `frontend/pages/plan/params/params.wxml`
- `frontend/pages/plan/result/result.wxml`
- `frontend/pages/discover/input/input.wxml`
- `frontend/pages/discover/result/result.wxml`
- `frontend/pages/profile/profile.wxml`
- `docs/*.md`

建议修改点：

- 检查所有中文是否出现乱码。
- 统一改成简洁中文，不保留测试口吻、英文标签、旧占位符。
- 首页、结果页、授权页、错误提示页优先处理。

验收标准：

- 微信开发者工具中所有页面中文正常显示。
- 终端或文档中不再出现明显乱码内容。
- 关键按钮文案不超过 8 个中文字符，关键说明不超过 2 行。

### P0-02 首页升级为“出发决策页”

目标文件：

- `frontend/pages/index/index.wxml`
- `frontend/pages/index/index.wxss`
- `frontend/pages/index/index.js`

建议修改点：

- 首页首屏保留旅行氛围背景，但减少长段说明。
- 两个主入口改为更直接：
  - “已经想好去哪”进入行程规划。
  - “还没决定去哪”进入随机玩。
- 增加“继续上次规划”入口，如果本地有最近草稿或最近行程。
- 首页不展示虚假承诺，不写“完全过滤广告”这类无法证明的话。

验收标准：

- 用户 3 秒内能判断该点哪个入口。
- 首屏不需要阅读长文案就能开始。
- 有最近数据时能继续上次行程；没有时不显示空壳模块。

### P0-03 目的地选择页重构为轻量选择器

目标文件：

- `frontend/pages/plan/destination/destination.wxml`
- `frontend/pages/plan/destination/destination.wxss`
- `frontend/pages/plan/destination/destination.js`

建议修改点：

- 降低大段 hero 的比重，把重点放到搜索、已选、列表。
- 搜索框固定在上方内容区，已选目的地横向可滑动。
- 省、市、区县选择保留，但减少说明文字。
- 所有箭头、关闭、删除图形使用 CSS 或本地图标，不用文本符号。

验收标准：

- 选择 1 个城市到进入下一步不超过 3 次点击。
- 多选目的地时，已选列表不会挤压主内容。
- 小屏宽度下无文字重叠、按钮溢出。

### P0-04 行程参数页升级为“旅行偏好配置”

目标文件：

- `frontend/pages/plan/params/params.wxml`
- `frontend/pages/plan/params/params.wxss`
- `frontend/pages/plan/params/params.js`

建议修改点：

- 表单内容按“日期和天数、预算、旅行偏好、补充说明”分组。
- 天数用更直观的步进器或滑动选择，避免大面积说明。
- 偏好卡保留图片图标，但统一尺寸、选中态和按压反馈。
- 生成按钮底部固定，按钮上方展示简短摘要：目的地、天数、预算。

验收标准：

- 首次进入时默认值合理。
- 用户修改参数后返回再进入，草稿能正确恢复。
- 生成前会触发登录授权，授权失败不丢失参数。

### P0-05 行程结果页升级为“可编辑路线”

目标文件：

- `frontend/pages/plan/result/result.wxml`
- `frontend/pages/plan/result/result.wxss`
- `frontend/pages/plan/result/result.js`

建议修改点：

- 结果顶部展示路线摘要：目的地、日期、天数、预算、偏好。
- 每天行程改为时间线结构，少用大卡片。
- 每个地点默认只展示名称、时段、时长、地址、交通到下一站。
- 推荐理由、提示、参考链接放入“展开详情”。
- 增加统一编辑入口：替换、备注、删除、上移、下移。
- 保存、复制、分享放到统一操作栏。

验收标准：

- 用户能快速扫完整个路线，不被长文案淹没。
- 每个行程项都有明确的编辑入口。
- 删除、替换、备注后保存状态正确。
- 加载、失败、超时、后端未启动状态都清楚。

### P0-06 随机玩升级为“附近灵感探索”

目标文件：

- `frontend/pages/discover/input/input.wxml`
- `frontend/pages/discover/input/input.wxss`
- `frontend/pages/discover/input/input.js`
- `frontend/pages/discover/result/result.wxml`
- `frontend/pages/discover/result/result.wxss`
- `frontend/pages/discover/result/result.js`

建议修改点：

- 输入页聚焦三个动作：定位出发地、选择天数预算、选择偏好。
- `wx.getLocation` 入口文案继续明确“主动点击、仅用于识别出发城市”。
- 推荐结果页改为可横滑推荐卡，突出目的地、距离、适合天数、预算、推荐理由。
- “生成行程”按钮必须把 discover context 完整传给规划结果页。
- 空推荐时提供“换一组条件”和“手动选城市”。

验收标准：

- 拒绝定位后可以手动选择城市继续。
- 推荐卡信息完整，不出现空白字段。
- 从推荐进入行程生成后，结果页能体现来源目的地和偏好。

## 4. P1 高价值升级

### P1-01 我的行程升级为“旅行档案”

目标文件：

- `frontend/pages/profile/profile.wxml`
- `frontend/pages/profile/profile.wxss`
- `frontend/pages/profile/profile.js`
- `frontend/services/trip.js`

建议修改点：

- 登录态、未登录态、空态、失败态统一视觉。
- 行程列表增加来源标签：规划、随机玩。
- 增加排序：最近更新、出发日期。
- 增加继续编辑、再次生成、删除确认。

验收标准：

- 首次进入“我的”会触发登录授权弹窗。
- 行程列表加载不重复请求。
- 删除后列表即时更新。

### P1-02 统一错误与状态系统

目标文件：

- `frontend/services/api.js`
- `frontend/services/backend-health.js`
- `frontend/constants/messages.js`
- 所有页面 JS/WXML

建议修改点：

- 新增 `frontend/constants/messages.js` 管理错误文案。
- 区分：网络断开、后端未启动、请求超时、登录失效、参数缺失、空数据。
- 页面内错误优先使用 inline state，toast 只用于轻量反馈。

验收标准：

- 同类错误只出现一套说法。
- 行程生成超时不误报为后端未启动。
- 后端真的无法连接时，提示开发者检查后端服务。

### P1-03 性能与缓存收口

目标文件：

- `frontend/services/api.js`
- `frontend/services/trip.js`
- `frontend/services/discover.js`
- `frontend/services/region-db.js`
- `frontend/pages/plan/result/result.js`
- `frontend/pages/profile/profile.js`

建议修改点：

- 减少同步 storage 大对象读写。
- 行程参数、推荐参数、最近行程用轻量摘要缓存。
- 对 `setData` 做切片更新，不整量刷新大对象。
- 历史行程列表和地区数据增加本地缓存命中。

验收标准：

- 页面切换不卡顿。
- 重进 profile 不重复登录、不重复拉取。
- 地区选择页第二次打开明显更快。

### P1-04 视觉资源补齐

目标文件：

- `frontend/assets/backgrounds/*`
- `frontend/assets/icons/*`
- `frontend/assets/pref-icons/*`
- `frontend/constants/index.js`

建议修改点：

- 增加 3-5 张更真实的旅行背景：城市清晨、海边、山路、古城、夜游。
- 增加行程项类型图标：景点、餐饮、住宿、交通、购物。
- 增加空态插图：无行程、无推荐、网络失败。
- 所有资源控制尺寸，避免小程序包体过大。

验收标准：

- 背景图不模糊、不抢文字。
- 图标风格统一，不再出现文本符号代替图形。
- 小程序包体保持在可接受范围。

## 5. P2 产品增强

### P2-01 行程编辑增强

建议功能：

- 拖拽或按钮排序。
- 备注编辑弹窗。
- 替换候选地点列表。
- 一键压缩行程或放松行程。

验收标准：

- 编辑后保存的数据与页面展示一致。
- 每次编辑都有明确反馈。

### P2-02 最近浏览与继续规划

建议功能：

- 首页展示最近一次规划草稿。
- 我的页面展示最近打开行程。
- 参数页支持恢复上次填写。

验收标准：

- 用户中断后能继续。
- 不把旧数据误带入新行程。

### P2-03 分享体验升级

建议功能：

- 分享标题包含目的地和天数。
- 分享图使用行程背景和摘要。
- 复制行程生成更清晰的文本格式。

验收标准：

- 分享给别人能看懂这是一份什么行程。
- 复制文本适合发到微信聊天。

## 6. 建议执行批次

### 第一批：体验基线修复

目标：先消除割裂感和明显问题。

任务：

- 修复中文乱码与文案。
- 重做首页。
- 重做目的地选择页。
- 统一按钮、状态、底部操作栏。

验收：

- 首页到参数页视觉统一。
- 所有中文正常。
- 前端测试通过。

### 第二批：核心生成链路升级

目标：把“生成行程”变成可信、可编辑的路线结果。

任务：

- 重做参数页。
- 重做行程结果页。
- 完善编辑入口。
- 统一生成失败、超时、重试状态。

验收：

- 行程能生成、编辑、保存、复制、分享。
- 异常场景不误报。

### 第三批：随机玩产品化

目标：让随机玩成为真正可用的旅行灵感入口。

任务：

- 重做随机玩输入页。
- 重做随机玩结果页。
- 优化定位拒绝、空推荐、生成行程的闭环。

验收：

- 定位与手动选址都可用。
- 推荐结果信息完整。
- 推荐能稳定进入行程生成。

### 第四批：我的行程与长期使用

目标：提高留存和复用价值。

任务：

- 我的行程筛选、排序、继续编辑。
- 最近规划与最近浏览。
- 空态和登录态优化。

验收：

- 登录授权自然。
- 行程资产清晰。
- 列表加载稳定。

### 第五批：性能、资源与上线收口

目标：让项目适合真实发布和长期维护。

任务：

- storage 和 setData 性能优化。
- 图片资源压缩。
- 错误文案集中管理。
- 更新本地开发和部署文档。

验收：

- 全量前端测试通过。
- 后端健康检查通过。
- 微信开发者工具真机预览主链路通过。

## 7. 测试与验收要求

每一批完成后都必须跑：

```powershell
cd D:\软件开发\旅游小程序\frontend
node --test test/*.mjs
```

手动验收至少覆盖：

- 首页进入规划。
- 首页进入随机玩。
- 目的地选择到参数页。
- 参数页授权登录后生成行程。
- 行程结果保存、复制、分享、重试。
- 随机玩定位拒绝后手动选择城市。
- 随机玩推荐进入行程生成。
- 我的页面登录、列表加载、删除、重新进入。

后端本地运行检查：

```powershell
cd D:\软件开发\旅游小程序\backend
npx -y node@20 src/index.js
```

健康检查：

```powershell
curl http://127.0.0.1:3000/health
```

## 8. 暂不建议做的内容

以下内容先不做，避免项目变重：

- 不引入大型 UI 框架。
- 不做复杂社区、评论、动态流。
- 不做后台持续定位。
- 不做过度动画和长时间运行的装饰效果。
- 不把行程结果做成大段 AI 文章。
- 不在核心页面堆砌营销文案。

## 9. 完成定义

当以下条件满足时，本轮 UI 与功能升级可以视为完成：

- 核心页面视觉统一，旅行氛围明确。
- 主链路可用：规划、随机玩、保存、我的。
- 所有核心异常态都有清晰反馈。
- 行程结果可扫描、可编辑、可保存。
- 前端自动化测试全部通过。
- 微信开发者工具中小屏和常规屏无明显文字重叠。
- 本地运行文档、后端启动方式、接口地址说明清楚。
